# 어느 단계가 무엇을 읽나

> 상태: 작성완료
> 준수 강도: 필수
> 최종갱신: 2026-10-20

그 단계에 들어갈 때 연다. **`build-docindex.py` 가 이 파일의 표를 읽어 목차를 찍는다.**

---

**이 표가 정본이다.** 각 지침 파일은 자기가 몇 단계에서 읽히는지 적지 않는다 —
두 군데 적으면 어긋난다.

```
종류            단계                      무엇
────────────────────────────────────────────────────────────────
Linter          02 · 03 · 23 · 04 · 05 · TS   어기면 안 되는 것.  강도 필수
Architecture    02 · 03 · 04 · 06 · TS    무엇이 무엇을 부르나
Boilerplate     04                        화면 하나를 새로 만드는 단위
TechStack       03 · 04 · 05 · 06 · TS    언어 · 틀 · DB
reference       부를 때                    그 상황이 걸릴 때만
배포             06                        배포 절차와 값
공정지식          01                        현업이 쓰는 말과 업무 규칙
양식             05                        받은 제출 양식
솔루션            01 · TS                   무엇을 하는 시스템인가 · 운영
개발             04                        techbase 가 빈 시스템의 대체
테스트            05                        받은 테스트 절차
명세             02 · 04                   테이블 · 컬럼
이력             부를 때                    그 화면을 건드릴 때만
프로젝트          부를 때                    끝난 프로젝트 문서 묶음
```

**이 표가 「종류 → 단계」의 정본이다.** 문서는 자기가 무슨 종류인지만 머리말 `종류:` 에
말하고, 언제 읽히는지는 모른다. 그래야 정책을 바꿀 때 **여기 한 줄만** 고친다 —
문서 94개에 흩어 놓으면 「04 에서 Boilerplate 그만 읽자」에 다섯 파일을 고쳐야 한다.

지침 넷(`Linter`·`Architecture`·`Boilerplate`·`TechStack`)과 `reference` 는
**파일명이 종류를 말하므로** 머리말을 안 봐도 된다. 받은 문서는 파일명으로 모르니 적는다.

### 과거 이력 — 어느 단계가 무엇을 보나

지침과 별개 축이다. 이력은 **화면**으로 찾고, 자리는 그 시스템 문서 5절 자동구역이다.

| 단계 | 보나 | 무엇을 |
|---|:-:|---|
| 01 Requirements | ✗ | 코드를 안 보는 단계다 |
| 02 Analysis | **O** | 같은 화면·같은 증상이 있었나. 이미 다뤄진 건인지 먼저 본다 |
| 03 Design | **O** | 과거 `03-design` — **왜 그렇게 설계했나.** 지금 뒤집으려는 게 그때의 결정일 수 있다 |
| 04 Development | ✗ | 구현 중에 이력을 뒤지면 손이 멈춘다. 볼 것은 03 에서 봤다 |
| 05 Testing | **O** | 과거 `05-testing` — **회귀 테스트 목록이 거기 있다** |
| 06 Deployment | **O** | 순서 · 롤백 · 그때 걸렸던 것 |
| TS | **O** | 과거 `01-troubleshooting` 4절 「배제한 것」 — 같은 길을 두 번 파지 않는다 |

**전문을 훑지 않는다.** 5절 이력 자동구역이 **화면코드로 묶어** 두었으니
그 화면 줄만 보고 고른 것을 연다.

### 남의 시스템 이력도 본다 — 02 · TS

`related` 가 **`층구분` 또는 `공정흐름`** 으로 가리키는 시스템만 본다.
`모듈사본`·`번호충돌`·`기능중복` 은 **안 본다** — 코드가 닮았을 뿐 같은 소재가 흐르지 않는다.

**무엇을 여는지가 정해져 있다.** 전부 훑지 않는다.

```
1  그쪽 {시스템코드}-OVERVIEW.md 5절 이력 자동구역
     화면코드별로 묶여 있다. 날짜와 폴더명만 보고 고른다
2  고른 작업 폴더의 readme-{SR번호}.md
     한 줄 요약(description)으로 이번 건과 걸리는지 판정한다
3  걸리면 아래 하나를 연다
```

| 왜 보나 | 그쪽에서 여는 것 | 실물 |
|---|---|---|
| 02 — 같은 증상이 있었나 | `01-troubleshooting` 4절 「배제한 것」 | 4건 |
| 02 — 무슨 일을 했나 | `02-analysis` | **22건** |
| TS — **무엇이 바뀌어 깨졌나** | `03-design` 머리말 `변경예정파일` | **21건** |
| TS — 실제로 뭐가 나갔나 | `06-deployment` 머리말 `체인지셋` | **2건** |

**마지막 줄이 함정이다.** 체인지셋이 적힌 문서가 둘뿐이라 「실제로 무엇이 나갔나」로는
거의 못 찾는다. **`03-design` 의 `변경예정파일` 이 지금 가장 가까운 대용**이고,
그건 예정이지 실제가 아니다. 그 차이를 알고 본다.

### 왜 남의 것까지 보나

**화면 축이 층을 못 건넌다.** MES `MESD400E03` 과 LEVEL2 `ABCD300E12` 는
코드 체계가 달라 같은 화면으로 안 걸린다. 이름으로는 영영 안 만난다.

실측이 이유다 — **TS 가 걸린 화면 13개 중 10개(77%)가 SR 이력도 가진 화면**이었다.
장애의 범인은 과거 장애가 아니라 **과거 변경**일 때가 많은데, 층이 다르면 그 변경이 안 보인다.

**상대 이력이 0건이면 「없다」고 말하고 넘어간다.** 다른 시스템 것을 끌어다 쓰지 않는다.

### 단계에서 거꾸로 보면

| 단계 | 읽는 종류 | 과거 이력 |
|---|---|---|
| 01 Requirements | 공정지식 · 솔루션 | |
| 02 Analysis | **Linter** · Architecture · 명세 | **O** 같은 화면 + **related 의 층구분·공정흐름** |
| 03 Design | **Linter** · Architecture · TechStack | **O** 과거 `03-design` |
| 23 Analysis·Design | 위 둘의 합집합 | **O** 위 둘의 합집합 |
| 단건 | **Linter** 하나 | |
| 04 Development | **Linter** · Architecture · Boilerplate · TechStack · 개발 · 명세 | |

**Linter 를 설계 단계에서 읽는 이유.** 2026-10-20~22 에 같은 일이 세 번 났다 —
설계가 「공통으로 빼지 않는다」로 정하고, 04 가 Linter 를 읽고 「두 화면이 같은 일을
하면 Define.cs 에 모은다」(강도 **필수**)를 보고 **뒤집었다.**

**Linter 는 코딩 규칙만 든 문서가 아니다.** 「금지」 절에 든 것은 대부분 설계 결정이다 —
무엇을 공통으로 뺄지, 새 패턴을 만들어도 되는지, 어느 버전에 묶여 있는지.
**설계를 정하고 나서 읽으면 정한 것을 무르게 된다.**

읽는 양이 늘지만 한 사이클을 통째로 없앤다. 04 에서 다시 읽는 것은 그대로 둔다 —
그때는 「만지기 전 확인」 절이 필요하고, 그건 설계 때 쓸 일이 없다.
| 05 Testing | **Linter** · TechStack · 양식 · 테스트 | **O** 과거 `05-testing` 회귀 목록 |
| 06 Deployment | Architecture · TechStack · 배포 | **O** 과거 `06-deployment` |
| TS | **Linter** · Architecture · TechStack · 솔루션 | **O** 과거 4절 「배제한 것」 + **related 의 층구분·공정흐름** |

**「그 단계가 부르면 무조건 읽는다.」** 강도와 무관하다 — `TechStack` 은 강도가 `참조`
지만 다섯 단계에서 읽는다. 강도는 **읽은 다음 어겨도 되나**를 말한다.

각 시스템 문서 5절의 목차가 이 표와 문서 머리말을 합쳐 찍힌다.
**표를 고치면 목차 열둘이 따라온다.** 찍는 것은 `hooks\scripts\build-docindex.py` 다.

### 목차에 없는 것을 찾을 때

`hooks\scripts\find.py` 가 **머리말만** 훑는다 — `description` · 제목 · `종류` · `system`.

    python find.py {wiki} A공정 --type overview
    python find.py {wiki} --kind 배포

**본문은 안 본다.** 전문을 훑으면 관련도 높은 한 조각이 딸려 와서, 지침 네 줄 중
한 줄만 읽고 나머지 셋을 어기는 일이 생긴다. 고를 근거만 주고 **여는 것은 판단이다.**
