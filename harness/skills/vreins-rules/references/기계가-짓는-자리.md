# 기계가 짓는 자리 — 손으로 고치지 않는다

> 상태: 작성완료
> 준수 강도: 필수
> 최종갱신: 2026-10-20

목차·이력을 찍거나 그것이 틀렸을 때 연다.

---

**손으로 고치지 않는다.** 손으로 적는 칸은 안 적히거나 굳는다. 정본은 다른 데 있고
아래 셋은 그것을 모아 찍은 것이다 — 손으로 고친 줄은 다음 생성 때 사라진다.

    {코드}-OVERVIEW.md 5절 「읽을 문서」    build-docindex.py   4절 표 + 각 문서 머리말 `종류:` · `description:`
    {코드}-OVERVIEW.md 5절 「이력」        build-history.py    ls {화면대역}\ 가 주는 폴더명 그대로
    _manual\{코드}-INDEX.md 폴더 목록       build-docindex.py   그 폴더에 있는 것 전부, 종류별로

틀렸으면 **정본을 고친다.**

    목차 줄이 비었다          그 문서 머리말에 description 이 없다
    목차 단이 틀렸다          그 문서 머리말 `종류:` 가 없거나 4절 표에 없는 값이다
    이력에 안 보인다          폴더 이름이 규약({YYMM}-{구분}-{제목})과 다르다

**위키 전체 목차(`index.md`)는 없다.** 2026-09-28 에 지웠다 — 네 절 중 셋이 파생값이었고
위험 표는 옵시디언 백링크가 대신한다. **폴더가 목록이다.** SR 은 `ls {유형}\{시스템}\{화면대역}\` 로,
문서는 `find.py` 로 찾는다(4절). 없는 목차 파일을 있는 것처럼 가리키지 않는다.

검사는 `hooks\scripts\lint.py {wiki}` 다. 단계 끝에 돌릴 때는
`--only {세션 폴더}` 를 붙인다 — 위키 전체(258개)를 훑을 이유가 없다.
그때는 시스템 정의 대조를 건너뛴다(그건 전체를 봐야 하는 검사다). **형태만 본다** — 머리말 · 절 구성 · `related` 와 2절 표의
일치 · 시스템 정의와 위키 시스템의 일치. 내용이 맞는지는 판정하지 않는다.

### 제출용 엑셀도 파생값이다

    단위테스트결과서_{SR번호}_v1.0.xlsx   export-testing-xlsx.py   05-testing-{SR번호}.md

05 단계를 끝낼 때 찍는다. **엑셀을 고치지 않는다** — 다음에 찍으면 덮인다.
고칠 것은 `05-testing-{SR번호}.md` 에서 고치고 다시 찍는다.

    python hooks\scripts\export-testing-xlsx.py {05-testing-*.md}

외부 패키지를 쓰지 않는다. xlsx 는 zip 안의 XML 이고 표준 라이브러리로 쓴다 —
`pip install` 을 요구하면 사내망에서 막히는 날 「엑셀만 안 나오는」 고장이 되고,
그 사람은 제 문서를 의심한다.
