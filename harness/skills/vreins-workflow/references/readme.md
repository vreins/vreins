# readme — 작업 폴더 표지

> 준수 강도: 권장 — 목차는 필수, 표현은 자유 · 최종갱신: 2026-10-20
> **본문 한도 25줄.** 표지는 목차지 일지가 아니다. 쓰는 법 [[_간결]]

작업 폴더마다 하나. **단계 산출물이 아니라 그 폴더가 무엇인지 말하는 표지다.**
**세션을 열 때 먼저 만든다** — 표지가 없으면 목차가 그 폴더를 집지 못한다.

```
MES\MESD\400\                        ← 대역
  2609-SR2609-0142-온도보정기준변경\     ← 제목은 폴더명이 갖는다
    readme-SR2609-0142.md
    01-requirements-SR2609-0142.md
```

## 머리말

[[_공통]] 과 같고 아래 셋만 다르다.

```yaml
lane: quick       # 간이 차선일 때만. 분석 들머리에서 판정해 적는다
closed: 2026-09-30  # 끝났을 때만
```

`lane` 은 **02·03 이 없는 이유를 말한다.** 없으면 다음 세션이 「안 한 것」으로 읽고
되돌아간다. 상태 파일이 아니라 차선 표식이다 — 어디까지 했나는 여전히
그 단계 문서가 있느냐가 말한다.

**번호가 없으면 `id` 를 폴더 이름에서 끌어온다** — `2610-TS-실적전송지연장애`
→ `id: TS-실적전송지연장애`. 그것도 없으면 화면코드. `미정`·`TBD` 는 넣지 않는다 —
목차가 그것으로 문서를 집는다.

`type` 은 둘. `srs`(우리가 하는 것) · `fact`(남이 쓴 것을 받아 온 것).

## 본문

```markdown
# {작업 폴더 이름}

## 무슨 작업인가
한두 문장. 상세는 01·분석이 갖는다.

## 산출물
| 단계 | 문서 |
|---|---|

## 진행
지금 어디까지. 단계 문서가 정본이고 여기는 사람이 읽는 요약이다.
```

**업무 내용을 길게 쓰지 않는다.** 표지가 두꺼워지면 단계 문서를 안 읽게 된다.

### 해당 없는 단계는 사유를 적는다

```
| 06 배포 | 해당 없음 — 형상관리를 쓰지 않는 시스템이라 올릴 자리가 없다 |
```

**그 한 줄이 그 단계의 산출물이다.** 비우면 「안 했다」와 「해당 없다」가 섞인다.

## 받아 온 기록

남이 쓴 것을 옮겼으면 `type: fact` 로 하고 **출처를 남긴다.**

```yaml
type: fact
출처: { 저장소: "...", 경로: "...", 작성자: "..." }
```

본문에는 **무엇을 손댔는지** 적는다 — 파일명 매핑, 링크 재지정.
**맞춤법·표현은 건드리지 않는다.** 남의 글이다.
우리 값 밖의 키는 지우지 말고 이름만 바꾼다 (`status:` → `원본status:`).

## 요약값을 표지에 올릴지

**안 올린다.** 정본은 그 값을 만든 단계 문서다 — 영향범위는 분석, 변경예정파일은
설계, 체인지셋은 배포. 표지에 같이 적으면 어긋난다. 옛 상태 파일을 없앤 이유가
그것이다(41건 중 37건이 어긋나 있었다).

**남은 질문** — 목차 생성기가 표지만 읽는지. 읽으면 사본이 필요해진다. 위키 담당(sye).
