# readme — 작업 폴더 표지

> 상태: 부분작성
> 준수 강도: 권장 — 목차 구조는 필수, 표현은 자유
> 최종갱신: 2026-09-21

작업 폴더마다 하나씩 있다. **단계 산출물이 아니라 그 폴더가 무엇인지 말하는 표지다.**

> **본문 한도 25줄** (머리말 제외). 표지는 목차지 일지가 아니다 — 진행 이력이 길어지면 줄인다. [[_간결]]

파일 이름은 `readme-{SR번호}.md` 다. 단계 문서도 같은 키를 쓴다.

```
MES\MESD\400\                          ← 대역.  시스템이 정한 축으로 자른다
  2609-SR2609-0142-온도보정기준변경\           ← 제목은 폴더명이 갖는다
    readme-SR2609-0142.md
    01-requirements-SR2609-0142.md
    02-analysis-SR2609-0142.md
    ...
```

**제목을 파일명에 안 쓴다.** 한 폴더 안에서 같은 제목이 예닐곱 번 반복되고,
길면 25자가 넘는다. SR번호는 짧고 **볼트 전체에서 유니크**하며 ITS 에서 찾을 때
쓰는 키라 실무에도 맞는다.

**SR번호가 없으면** 화면코드를 쓴다(`readme-MESD400E03.md`).
그것도 없으면 `TS-{YYMMDD}` 로 만든다.

## 세션을 열 때 먼저 만든다

**폴더만 만들고 단계 문서부터 쓰지 않는다.** 표지가 없으면 그 폴더가 무엇인지
목차가 집지 못한다.

## 머리말

```yaml
---
type: srs
id: SR2609-0142
system: ABCD
techbase: [Acme_Level2_UI, Acme_Level2_TASK]
화면코드: [ABCD100E01]     # 고친 화면. 없으면 빼지 말고 [] 로 둔다
화면대역: "100"            # 화면코드 5~7자리
description: 한 줄 요약     # 목차가 이걸 긁어 간다
updated: 2026-09-21
---
```

**간이 차선이면 한 줄을 더한다.** 01 끝에 판정해서 적는다.

```yaml
lane: quick     # 적지 않으면 정식이다. 조건은 vreins-workflow 스킬
```

**이것이 02·03 이 없는 이유를 말한다.** 없으면 다음 세션이 「안 한 것」으로 읽고
되돌아간다. 상태 파일이 아니라 **차선 표식**이다 — 어디까지 했는지는 여전히
그 단계 문서가 있느냐가 말한다.

작업이 끝나면 더한다.

```yaml
closed: 2026-09-30
```

**번호가 아직 없으면 `id` 를 폴더 이름에서 끌어온다** — `{구분}-{제목}`.

```
2610-TS-실적전송지연장애        →  id: TS-실적전송지연장애
2609-SR-HEAT번호체계변경        →  id: SR-HEAT번호체계변경
```

`미정` · `TBD` 같은 값을 넣지 않는다. **목차가 그것으로 문서를 집는다.**
번호가 나오면 폴더 이름과 `id` 를 같이 바꾼다.

`type` 은 둘뿐이다.

```
srs    우리가 진행하는 SR · SM · TS
fact   남이 쓴 기록을 받아 온 것. 아래 참조
```

## 본문

```markdown
# {작업 폴더 이름}

## 무슨 작업인가
한두 문장. 상세는 01·02 가 갖는다.

## 산출물
| 단계 | 문서 |
|---|---|

## 진행
지금 어디까지 왔나. **단계 문서가 있느냐가 정본이고 여기는 사람이 읽는 요약이다.**
```

**여기에 업무 내용을 길게 쓰지 않는다.** 표지가 두꺼워지면 단계 문서를 안 읽게 된다.

### 해당 없는 단계는 산출물 표에 사유를 적는다

문서를 안 만드는 단계가 있다 — 올릴 것이 없는 06 이 대표적이다.
**그 칸을 비워 두지 않는다.** 비우면 「안 했다」와 「해당 없다」가 구분되지 않고,
다음 세션이 그 단계를 다시 하려 든다.

```
| 05 테스트 | 05-testing-SR2609-0142.md |
| 06 배포   | 해당 없음 — 형상관리를 쓰지 않는 시스템이라 올릴 자리가 없다 |
```

**이 한 줄이 그 단계의 산출물이다.**

## 받아 온 기록

남이 쓴 문서를 옮겨 온 경우 `type: fact` 로 하고 **출처를 반드시 남긴다.**

```yaml
type: fact
출처:
  저장소: "http://{git-서버}/{위키-저장소}.git"
  경로: domain/mes/modules/MESG/troubleshooting/2026-06-29-....md
  작성자: {작성자}
```

본문에는 **무엇을 손댔는지** 적는다 — 파일 이름 매핑, 링크 재지정, 원본에 없던
키를 더한 것. **맞춤법·표현·문장은 건드리지 않는다.** 남의 글이다.

우리 값 집합 밖의 키는 지우지 말고 이름만 바꿔 남긴다 (`status:` → `원본status:`).
