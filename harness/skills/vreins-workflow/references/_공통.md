# 모든 단계 산출물에 같은 것

> 준수 강도: 필수 · 최종갱신: 2026-10-20

파일명과 머리말은 단계마다 같다. 전에는 양식 일곱 벌에 같은 글이 각각 있었다 —
한 벌을 고치면 나머지 여섯이 낡았다.

## 파일 이름

```
{단계번호}-{단계이름}-{SR번호}.md
```

제목은 **폴더명이 갖는다.** `20260714_SR2607-01292_규격별중량구간기준변경`
→ `03-design-SR2607-01292.md`

번호가 앞인 이유는 폴더에서 단계 순으로 서기 위해, SR번호를 붙이는 이유는
같은 제목이 수백 개가 되면 탭·검색에서 구분이 안 되기 때문이다.

## 머리말

**빼면 목차가 이 문서를 집지 못한다.**

```yaml
---
type: srs
id: SR2607-01292
system: MESD
techbase: [Acme_ERP_MES_V6]   # 위키 {유형}/COMMON/_manual/ 의 파일명 앞부분 그대로
화면코드: [MESD610Q06]          # 고친 화면. 없으면 [] 로 둔다
화면대역: "610"                 # 화면코드 5~7자리
description: 한 줄 요약          # 목차가 이걸 긁어 간다
updated: 2026-07-14
---
```

분석 단계(02 또는 23)만 한 줄 더. **이후 단계가 이것만 읽는다.**

```yaml
영향범위: [Acme_ERP_MES_V6]
```

## 빈 절

셋 중 하나. **빈 절은 누락과 해당 없음이 구분되지 않는다.**

```
내용                 쓸 것이 있다
「해당 없음」          이 작업에 없다는 판단
<!-- UNWRITTEN -->   알아야 하는데 아직 모른다
```

## 분량

한도와 규칙은 [[_간결]] 이 정하고 린터가 센다. 셋만 짚는다.

```
두괄식          절의 첫 줄이 결론. 근거는 그 뒤
개조식          항목으로 끊고 명사형으로 끝낸다 — ~함 · ~음. ~하였습니다 안 쓴다
사유는 서술 한 줄  「왜 그렇게 정했나」만 예외. 개조식만 쓰면 사유가 사라진다
두 번 안 적는다   앞 단계가 적은 것은 번호로 건다
코드를 안 적는다   소스가 정본이다. 인용은 한두 줄까지
```

**모르면 쓰지 말고 묻는다.** 추측을 문장으로 채우는 것이 분량의 가장 큰 원인이다.
