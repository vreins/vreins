# 모든 단계 산출물에 같은 것

> 상태: 작성완료
> 준수 강도: 필수
> 최종갱신: 2026-10-20

파일 이름 규칙과 머리말은 **단계마다 같다.** 전에는 양식 일곱 벌에 같은 설명이
각각 들어 있었다 — 한 벌을 고치면 나머지 여섯이 낡았고, 단계를 열 때마다
같은 글을 다시 읽었다. 여기 한 번만 적는다.

## 파일 이름

```
{단계번호}-{단계이름}-{SR번호}.md
```

제목은 **폴더명이 갖는다.** `20260714_SR2607-01292_규격별중량구간기준변경` 이면
`03-design-SR2607-01292.md` 다.

**번호를 앞에 두는 이유** — 폴더 안에서 단계 순으로 서고, 「설계 문서만」 같은 걸 고를 수 있다.
**SR번호를 붙이는 이유** — 같은 이름이 수백 개가 되면 탭·검색·그래프에서 구분이 안 된다.
제목은 25자가 넘고 한 폴더 안에서 예닐곱 번 반복된다. SR번호는 짧고 유니크하다.

## 머리말

**빼면 목차가 이 문서를 집지 못한다.**

```yaml
---
type: srs
id: SR2607-01292
system: MESD
techbase: [Acme_ERP_MES_V6] # 위키 {유형}/COMMON/_manual/{기술기반}-*.md 의 앞부분 그대로
화면코드: [MESD610Q06]               # 고친 화면. 「이 화면 앞서 누가 고쳤나」를 기계가 센다
화면대역: "610"                      # 화면코드 5~7자리
description: 한 줄 요약               # 목차가 이걸 긁어 간다. 없으면 목차에서 고를 수 없다
updated: 2026-07-14
---
```

분석 단계(02 또는 23)만 한 줄을 더 갖는다. **이후 단계가 이것만 읽는다.**

```yaml
영향범위: [Acme_ERP_MES_V6]    # 판정 결과
```

## 빈 절

셋 중 하나를 적는다. **빈 절은 누락과 해당 없음이 구분되지 않는다.**

```
내용                 쓸 것이 있다
「해당 없음」          그 항목이 이 작업에 없다는 판단
<!-- UNWRITTEN -->   알아야 하는데 아직 모른다
```

## 분량

**[[_간결]] 가 한도와 규칙을 정한다.** 문서마다 줄 수 한도가 있고 린터가 센다.
여기서는 셋만 짚는다 — 나머지는 그쪽에 있다.

```
짧게 쓴다        절을 채우려고 글을 늘리지 않는다. 한 줄로 끝나면 한 줄로 끝낸다
두 번 적지 않는다  앞 단계가 적은 것은 번호로 건다. 옮기면 한쪽이 낡는다
코드를 안 적는다   소스가 정본이다. 인용은 한두 줄까지. 그 이상은 파일:줄 로 가리킨다
```

**모르면 쓰지 말고 묻는다.** 추측을 문장으로 채우는 것이 분량의 가장 큰 원인이다.
