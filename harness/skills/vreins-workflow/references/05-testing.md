> 준수 강도: 권장 — 목차 구조는 필수, 표현은 자유
> 최종갱신: 2026-09-21

`05-testing-{SR번호}.md` 를 이 목차대로 쓴다.

파일 이름은 `05-testing-{SR번호}.md` 다. 제목은 폴더명이 갖는다 —
`20260714_SR2607-01292_규격별중량구간기준변경` 이면 `05-testing-SR2607-01292.md` 다.
**번호를 앞에 두는 이유** — 폴더 안에서 단계 순으로 서고, 「설계 문서만」 같은 걸 고를 수 있다.
**SR번호를 붙이는 이유** — 같은 이름이 수백 개가 되면 탭·검색·그래프에서 구분이 안 된다.
제목은 25자가 넘고 한 폴더 안에서 예닐곱 번 반복된다. SR번호는 짧고 유니크하다.

머리말은 이렇게 연다. **빼면 목차가 이 문서를 집지 못한다.**

```yaml
---
type: srs

system: MESD
techbase: [Acme_ERP_MES_V6] # 위키 {유형}/COMMON/_manual/{기술기반}-*.md 의 앞부분 그대로
화면코드: [MESD610Q06]               # 고친 화면. 「이 화면 앞서 누가 고쳤나」를 기계가 센다
화면대역: "610"                      # 화면코드 5~7자리
description: 한 줄 요약               # 목차가 이걸 긁어 간다. 없으면 목차에서 고를 수 없다
updated: 2026-07-14
---
```

## 1. 테스트 범위

무엇을 봤고 무엇을 안 봤는지. **안 본 것을 적는 절이다.**

## 2. 케이스와 결과

| # | 테스트 Case | 조건 | 기대 | 결과 | 비고 |
|---|---|---|---|---|---|

**머리글을 바꾸지 않는다.** 제출용 엑셀이 이 이름으로 열을 찾는다 — 자리가 아니라
이름으로 찾으므로 순서는 바뀌어도 되지만, 이름을 바꾸면 그 열이 **빈 채로 나간다.**
`테스트 항목` · `테스트 방법 (데이터)` · `기대 결과` 도 같은 것으로 읽는다 —
그렇게 쓴 문서가 이미 쌓여 있다.

`###` 로 묶어 써도 된다. 그 소제목은 엑셀 **비고** 앞에 붙는다.

**`결과` 에는 본 것을 적는다.** 「정상작동」은 판정이지 결과가 아니다 —
무엇을 봤는지 적어 두면 다음 사람이 같은 것을 다시 보지 않는다.

## 3. 실패와 조치

| # | 구분 | 무엇이 틀렸나 | 조치 | 재시험 |
|---|---|---|---|---|

`#` 는 **2 절의 케이스 번호**다. 그 번호로 이어 붙여 엑셀 `결함 상태` 칸이 채워진다.
여기 없는 케이스는 그 칸이 빈다 — **결함 목록을 따로 만들지 않는 이유다.**
같은 것을 두 군데 적으면 한쪽이 낡는다.

`구분` 은 셋 중 하나다.

```
기존결함   원래 소스에 있던 것을 이번에 발견했다
신규결함   이번 작업 중에 생긴 것
후속과제   이번 범위 밖이라 안 고치고 넘긴다
```

## 제출용 엑셀

이 문서를 다 쓰면 **찍는다.** 묻지 않는다.

```
python {플러그인}\hooks\scripts\export-testing-xlsx.py 05-testing-{SR번호}.md
    → 같은 폴더에 단위테스트결과서_{SR번호}_v1.0.xlsx
```

시트 둘이다. `단위 테스트 결과` 는 현업 제출 양식 9열 그대로이고,
`개요` 는 머리말 · 1절 · 4절 · 5절이 간다 — 제출 양식에는 그것들이 들어갈 자리가
없는데, 버리면 **「안 본 것」이 사라진다.**

**엑셀을 고치지 않는다.** 정본은 이 마크다운이고, 다시 찍으면 덮인다.
B·D 열(`테스트 프로그램 ID` · `단위 Test ID`)은 머리말 `화면코드` 에서 나온다 —
비어 있으면 머리말을 채운다.
