작은 건은 조사와 판단이 한 호흡이라 나눌 자리가 없다.

**02 를 없애는 것이 아니다.** 어떤 건에서는 02 가 「`ExportToXlsx` 는 그리드를

**문서를 합치는 것이지 조사를 빼는 것이 아니다.** 영향범위도 여기 머리말이 갖는다.

## 2. 현재 동작과 코드의 말

어느 화면 · 어느 쿼리 · 어느 계층인가. 지금 어떻게 되어 있나.
화면을 확정해 **머리말 `화면코드`** 에 적는다.
**코드를 옮기지 않는다** — `파일:줄` 로 가리킨다.

## 3. 영향범위 판정

| 기술기반 | 걸리나 | 근거 |
|---|---|---|

결과를 **머리말 `영향범위`** 에.
**여기서 차선이 틀렸다고 드러날 수 있다** — 기술기반이 둘이거나 신규 파일이 생기면
간이 조건을 벗어난 것이다. 멈추고 보고한 뒤 정식으로 돌린다.

## 4. 변경 방침과 변경예정파일

왜 이 방법인가. Architecture 의 어느 규칙을 따랐나.

|---|---|---|

신규 / 수정 / 삭제. **한 파일이 한 줄.**
**코드를 적지 않는다** — 04 가 쓰고 소스가 정본이다.
