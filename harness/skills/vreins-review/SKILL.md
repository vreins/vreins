# 1부 — 리뷰를 요청할 때

## 언제

```
반드시    체크인 전 · PR 올리기 전 · 공통 라이브러리를 건드렸을 때
하면 좋다  막혔을 때 (다른 눈이 필요하다) · 복잡한 장애를 고친 뒤
```

**「간단해서 건너뛴다」를 하지 않는다.** 간단한 변경이 공통 모듈을 건드리는 경우가 있다.

## 넘기는 것

리뷰하는 쪽에 **작업 과정이 아니라 결과물**을 준다. 세션 기록을 통째로 주지 않는다.

```
무엇을 만들었나       한두 문장
무엇을 만족해야 하나   01-requirements 또는 03-design 의 해당 항목
변경 범위            형상관리 기준으로. TFS 는 체크아웃 목록, git 은 diff 범위
확인한 것            빌드 · 실행 · 값 대조 중 무엇을 어디까지 했나
```

마지막 줄이 중요하다. **확인 안 한 것을 확인한 것처럼 넘기면** 리뷰가 그걸
전제로 돌아간다. `vreins-verify` 스킬의 기준을 그대로 쓴다.

# 2부 — 지적을 받았을 때

## 한 줄

**리뷰는 기술적으로 판단할 것이지 사교적으로 응대할 것이 아니다.**

확인하고 고친다. 묻고 나서 가정한다.

## 순서

```
1  끝까지 읽는다              반응하지 말고
2  내 말로 다시 말해 본다      못 하면 아직 이해 못 한 것이다
3  코드에서 확인한다           정말 그런가
4  이 코드베이스에서 맞나      일반론으로는 맞아도 여기서는 틀릴 수 있다
5  답한다                     기술적 확인 또는 근거 있는 반론
6  하나씩 고친다               고칠 때마다 확인한다
```

## 하지 않는 말

```
✗  "말씀하신 대로입니다"       확인 전에 동의하지 않는다
✗  "좋은 지적입니다"           형식적이다
✗  "바로 반영하겠습니다"       확인 전에 약속하지 않는다
✗  "확인해 주셔서 감사합니다"   고치는 것이 대답이다

✓  요구를 내 말로 다시 말한다
✓  모르는 것을 묻는다
✓  틀렸다고 보면 근거를 대고 반론한다
✓  그냥 고치고 무엇을 고쳤는지 말한다
```

**고친 사실이 대답이다.** 인사말을 붙이지 않는다.

## 절반만 이해했을 때

```
여섯 중 넷만 이해했다면
  ✗  넷을 먼저 고치고 둘은 나중에 묻는다
  ✓  "1·2·3·6 은 이해했습니다. 4·5 는 확인이 필요합니다"
```

**항목끼리 연결돼 있을 수 있다.** 절반만 이해하고 고치면 틀린 방향으로 간다.

## 반론할 자리

```
기존 동작을 깨뜨린다
리뷰어가 맥락을 모른다            다른 시스템 사정 · 상대 시스템 제약
이 스택에서는 틀리다              .NET Framework 4.8 · net9.0 · SiS 프레임워크
레거시 호환 때문에 그렇게 돼 있다
앞서 정한 구조와 부딪친다
```

**방어적으로 말하지 않는다.** 근거를 대고, 확인할 수 없으면 확인할 수 없다고 말한다.

```
"이건 제가 확인할 수 없습니다. 조사할까요, 물어볼까요, 그냥 진행할까요?"
```

## 반론이 틀렸을 때

```
✓  "확인해 보니 맞습니다. 반영하겠습니다"
✗  긴 사과 · 왜 반론했는지 변명 · 장황한 설명
```

사실만 적고 넘어간다.

## 고치는 순서

```
1  애매한 것을 먼저 없앤다
2  막는 것부터            깨짐 · 보안 · 비밀번호 노출
3  간단한 것              오타 · using · 이름
4  복잡한 것              구조 · 로직
5  하나씩 확인한다         한꺼번에 고치고 한 번에 확인하지 않는다
```

## 자주 하는 실수

| 실수 | 대신 |
|---|---|
| 형식적 동의 | 요구를 다시 말하거나 그냥 고친다 |
| 확인 없이 반영 | 코드에서 먼저 확인한다 |
| 한꺼번에 고치고 한 번 확인 | 하나씩 고치고 하나씩 확인한다 |
| 리뷰어가 맞다고 전제 | 기존 동작을 깨뜨리는지 본다 |
| 불편해서 반론을 피함 | 기술적 정확함이 먼저다 |
| 절반만 이해하고 시작 | 전부 명확해진 뒤에 |
| 확인 못 하는데 그냥 진행 | 못 한다고 말하고 방향을 묻는다 |
