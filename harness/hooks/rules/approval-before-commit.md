# 승인 없이 커밋하지 않는다

> 상태: 작성완료
> 준수 강도: 필수
> 최종갱신: 2026-10-27

`git commit` · `git push` · `tf checkin` 은 **사용자 승인 뒤에** 한다.
승인은 「이 작업 해줘」가 아니라 **「커밋해도 된다」**여야 한다.
작업을 시켰다고 커밋까지 허락한 것이 아니다.

## 승인받기 전에 보여줄 것

    무엇이 바뀌었나      파일 목록. 추가 · 수정 · 삭제를 구분한다
    왜 바뀌었나          커밋 메시지 초안
    안 한 것이 있나      범위에서 뺀 것과 그 이유

`git diff` 를 보여줄 수 있으면 보여준다. **요약만 하고 커밋하지 않는다** —
요약은 사람이 못 보고 넘어간 것을 못 잡는다.

## 자동으로 하지 않는 것

    git push        소스 저장소는 승인 항목이 따로다 (위키는 예외 — 아래)
    브랜치 병합      PR 을 거친다
    tf checkin      TFS 는 되돌리기가 비싸다

## 위키는 커밋 승인에 푸시가 들어 있다

**단계 산출물 푸시는 따로 안 받는다.** 승인은 「이 단계가 맞다」는 뜻이고,
맞는 산출물을 내 PC에만 두는 것은 아무 의미가 없다 — **안 올라간 산출물은
없는 산출물이다.**

    위키            승인 → 커밋 → 푸시      한 번의 승인
    소스 저장소      승인 → 커밋             푸시는 따로 받는다

위키는 산출물만 들어가고, 가르는 것은 **읽는 사람이 다르다**는 점이다.
소스는 되돌리기가 비싸고 남이 받아 쓰지만, 위키는 안 올리면 아무도 못 본다.

## 체크아웃과 체크인

편집하려면 **체크아웃은 해야 한다** — 안 하면 편집 자체가 실패한다.
그건 작업의 일부라 승인 대상이 아니다. **체크인이 승인 대상이다.**

## 형상관리가 없는 시스템

`형상관리: 없음` 이면 되돌릴 수단이 없다. 그 경우 **고치기 전에** 원본을
어디에 남길지 먼저 확인한다.
